# v0.4.1 产品整改验收

验收目标：普通 Windows 用户获取运行器后，一次准备全部中文 32 章，让原来的
Agent 通过工具亲自玩；每次选择落盘，支持暂停恢复和读档分支。

## 已实现的用户流程

- 首页、CLI、MCP 默认《底特律》。缺少剧情时提示准备，不自动开始开发演示。
- 一次获取固定上游完整 ZIP，校验 SHA256，导入全部 32 章并保留署名和许可；
  离线可一次导入完整 ZIP。英文材料不会被误认成固定中文包。
- Windows x64 便携版包含 Python 和运行依赖；中文启动与故障说明。
- 自动生成本机实际路径的通用 MCP / 官方 DSH 配置，以及绑定已有存档的 Agent 指令。
- 每步返回当前场景与回执；历史按角色分页，不反复复制整部历史。
- 模型预算按剧情容量和章末摘要规划，金额由用户填写确认，不用默认 30 次假定通关。
- 玩家每章自行维护前情摘要，默认 5000 字且可调；新章前先整理，最终章也需整理。
  详见 [RECAPS.md](RECAPS.md)。
- 导入故事可以导出无剧情正文的活动统计分享候选，完整报告及摘要继续私人保存。

## 实际证据

整套免费测试 **186 项通过**，包括真实进程的 CLI/MCP、循环回放、预算与未知请求、
角色隔离、摘要精确字数、逐章模型请求、前缀稳定、崩溃恢复与分支后见信息隔离。
摘要模型测试使用假 HTTP Provider，没有付费调用。

固定 32 章的最终静态与脚本审查：260 节点、440 场景变体、429 结局引用，
未归属决策和缺失结局目标均为 0。128 条完整脚本路线通过，包含角色死亡、
诺丝接替、康纳替代机体及结局一致性检查；两种玩法分别完成实际存档接口的
32 章路线、暂停恢复和不覆盖原局的分支。细节与采样边界见
[DETROIT_COMPATIBILITY.md](DETROIT_COMPATIBILITY.md)。

安装的官方 DSH MCP 客户端 0.2.0-rc.2 在隔离工具作用域中实际发现并调用工具，
两种视角分别通过 32 章、167 次脚本选择，验证暂停、存档点、分支、原局和记忆
候选导出。紧凑响应也单独复验。这是实际 DSH 工具桥接，选择由脚本决定；
不声称一个新的 DSH 模型自主完成了这些路线。新增逐章摘要另有真实 MCP 与
假模型 HTTP 测试，构件检查会实际提交标明脚本用途的摘要并核对 Markdown。

Windows 构件检查校验 ZIP 的 SHA256，解压至包含中文和空格的路径，使用全新
存档目录并从子进程 PATH 移除系统 Python/Git，检查冻结 CLI、MCP、桌面服务、
实际上游下载和康纳第一章两种视角。构件发布前检查包含的源码与工作区字节一致，
没有存档、Core、密钥或第三方剧情目录。

隔离 Chromium 已实际验证首页一次获取全部 32 章、首个场景、刷新续用已安装剧情、
暂停恢复、选择、命名点、分支、活动统计下载与预算引导。桌面 DPR 1 / 1.5 和手机
视口均无溢出或脚本错误。见 [PRODUCT_UI_ACCEPTANCE.md](PRODUCT_UI_ACCEPTANCE.md)。

## 仍需诚实区分的边界

没有在另一台从未安装过软件的实体 Windows 电脑或完整新虚拟机上，使用新 DSH
模型从第 1 章自主玩到第 32 章。隔离目录、去除 PATH 的实测不能冒充这项验收。
静态检查和 128 条路线不穷尽所有状态组合。真实第三方剧情只在用户请求后从
上游获取；许可不代表原游戏权利方授权。软件发布不等于私人日志上传或 dots 已读取。
