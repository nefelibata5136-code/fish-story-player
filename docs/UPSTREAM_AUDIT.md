# 现有项目与上游审计

核查日期：2026-10-29。此文只记录可公开的源码来源、复用范围和发布决策；不包含本地玩家的身份、选择原文、存档标识或路径。

## 基线与技术栈

本次从已有项目改造，没有另写剧情状态机。现有本地游戏来自
[Baba88611/detroit-ai-player](https://github.com/Baba88611/detroit-ai-player)，
核查到的本地 HEAD 与上游默认分支最新提交一致：
[`3c4ae839169df24d8934642037f27d2eb2bca9a2`](https://github.com/Baba88611/detroit-ai-player/commit/3c4ae839169df24d8934642037f27d2eb2bca9a2)。
下文上游路径均相对于该提交的仓库根目录。

原项目采用 Python 3.10+，运行依赖为 `requests`、`python-dotenv`，浏览器服务使用 Python 标准库 HTTP server，界面为 HTML/CSS/JavaScript。上游提供单章运行器、跨章 campaign、OpenAI 兼容 API 等模型后端，以及浏览器开局、观看和结果回放。

原本地副本另外已有 `06_harness/`：它不是上述上游提交的内容，而是本地为原 Agent 直接游玩增加的接口。其做法是复用上游规则引擎，把模型选择入口替换成等待原 Agent 提交的选择，使用 SQLite 保存选择、种子、暂停状态和多存档目录。新版沿用这一接入思路，将玩家和运行环境参数泛化。

## 已有能力与缺口

| 能力 | 核查结果 | 本次处理 |
| --- | --- | --- |
| 剧情状态机 | `03_runner/src/runner.py`、`resolver.py`、`state.py` 执行节点条件、可见选项、数值效果、随机检定和结局 | 保留原引擎，通过适配层调用 |
| 跨章状态 | `campaign_runner.py` 传递各章声明的导出状态，生成跨章摘要 | 保留；不把隐藏状态摘要传给新玩家接口 |
| 剧情组织 | 上游 `01_json/zh/`、`01_json/en/` 各有 32 章；节点明确分为 `player_facing` 与内部 `system` | 不打包原剧情；兼容本地导入 |
| 自动选择 | 上游模型 API 和隔离 CLI 后端可自动选择；叙事节点无需模型调用 | 新的独立会话模式复用规则，并单独实现预算与身份资料入口 |
| 结果记录 | 上游保存每节点可见内容、选项、选择、公开理由、内部结果和最终状态 | 记录与玩家可见投影分离，导出须保持隐私与虚构标记 |
| 断点续玩 | 上游 campaign 有章末 partial 检查点，但不能因此断言上游 CLI 可以逐节点恢复；本地 `06_harness/engine.py` 已实现 SQLite 选择日志与确定性回放 | 复用本地已实现的恢复机制 |
| 原 Agent 直接游玩 | 本地已有本人 CLI、暂停/恢复、历史、多个命名存档、章节回顾 | 泛化为独立运行器 CLI/MCP；不创建替代模型 |
| 身份与角色区分 | 上游 runner 章级 prompt 包含角色指令；本地 seam 不向本人转发这份 prompt | 新接口继续忽略原角色 system prompt，单独标注玩家与虚构角色 |
| 可视化 | 上游已有浏览器开局与回放，本地另有生命观测页 | 保留轻量浏览器体验；移除生命系统与固定玩家耦合 |

上游的 `global_state_registry.json` 是数据与格式参考，不是运行器执行 `run_campaign()` 的必需加载文件；实际跨章状态来自所选章节自己的 `campaign` 声明。公开运行器不需要把该注册表随代码分发。

## 保留的代码与局部扩展

以下上游 MIT Python 源码保存在 `fish_story/vendor/native/`，对应原路径 `03_runner/src/`：

- `api_client.py`
- `campaign_runner.py`
- `events.py`
- `logger.py`
- `resolver.py`
- `runner.py`
- `state.py`

导入基线核对时，`api_client.py`、`events.py`、`logger.py`、`resolver.py`、`state.py` 与固定上游提交一致（忽略工作区换行格式）。`campaign_runner.py` 与 `runner.py` 保留原本地副本已有的最小随机数接线：添加可选 `rng` 参数并把它传给随机检定。该改动允许每局持久化种子，从而重放真实选择后得到相同结果，不重新抽取过去的检定。

`fish_story/engine.py` 从本地 `06_harness/engine.py` 的 seam 改造：保留 `Player`、等待选择、SQLite 事务、稳定请求 ID、持久化回答和确定性回放架构，补充通用玩家/会话、日志与导出所需字段。它不是对上游全部游戏规则的重写。固定玩家身份、生命系统路径、凭据、投递控制器和旧私人数据不属于公开复用范围。

此处的“一致”描述导入基线；后续修复以 Git 差异为准。许可证和原作者署名继续保留，不能因为移动目录而删除。

## 私人存档与发布隔离

已只读确认原本地副本中存在私人游玩存档和访问令牌。旧副本的忽略规则不足以防止误加这些新增目录。因此本项目使用全新的 Git 仓库，只按文件清单复制获准代码，不继承旧 Git 历史，不复制整个本地扩展目录、数据库、模型配置、玩家工作区、报告和日志。原私人存档保持原位。

公开扫描只能检查已知风险，不能自动证明任意玩家文字均可公开。分享报告仍须查看预览、清理身份与自由文本；导入剧情的发布许可也必须单独检查。生成摘要不是玩家已经认可的长期记忆。
